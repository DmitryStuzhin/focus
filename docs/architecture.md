# Архитектура Focus

## Состояние сервера (ТЗ №13)

Версия 0.1.0 рассчитана на один активный процесс приложения. В SQLite сохраняются аккаунты, квоты провайдеров, облачные копии, публикации, результаты фоновых задач и попытки входа. Дневные и месячные бюджеты провайдеров сохраняются при перезапуске.

Минутные лимиты чата и поиска, дневной предел числа поисков Tavily и снимки поисковой выдачи находятся в памяти процесса. После перезапуска эти счётчики обнуляются. Если пропал снимок поиска, приложение просит повторить поиск. Сохранённые денежные лимиты продолжают действовать. Перед запуском нескольких экземпляров перенесите счётчики и снимки в общее хранилище, а запуск фоновых задач — в механизм с единым владельцем задачи.

## Поиск по рабочему пространству (ТЗ №15)

Диалоги, проекты и имена файлов индексируются в Web Worker. Для небольших текстовых файлов worker читает также содержимое. Индекс обновляется по изменившимся записям при поиске. Файлы Office доступны по имени. Специализированный поиск строк по файлам проекта остаётся отдельной операцией.

## Контекст модели (ТЗ №16)

Поиск контекста использует BM25 по содержимому до 60 небольших файлов с отдельным весом имени. В запрос попадает до пяти релевантных фрагментов с общим лимитом текста. Для диалогов длиннее 40 сообщений Focus добавляет ограниченную извлекающую выжимку старых реплик. Выжимка строится в браузере без вызова модели.

## Статический анализ (ТЗ №23)

В CI используется зафиксированная версия Biome для модулей доверия к прокси и поискового worker. Типы в этих модулях описаны через JSDoc с `@ts-check`. Правила можно расширять по мере форматирования остальных модулей. Среда выполнения остаётся без npm-зависимостей.

## Модули и поток запроса (ТЗ №29)

| Модуль | Ответственность |
| --- | --- |
| `public/` | Интерфейс, локальные данные, индекс поиска, выбор вложений, импорт и экспорт |
| `scripts/server.mjs` | Node HTTP, определение адреса клиента, граница сессии и вызов Worker |
| `scripts/auth.mjs`, `accounts.mjs`, `admin.mjs` | Аккаунты, почтовые коды, подписки, сессии, администрирование |
| `scripts/budget.mjs` | Атомарное резервирование токенов и денег в SQLite |
| `worker/api.js` | Проверка входных данных, локальные навыки, запросы к провайдерам и нормализация ответа |
| `scripts/workspace.mjs`, `jobs.mjs` | Снимки аккаунта, опубликованные страницы и фоновые исследования |
| `scripts/build.mjs` | Сборка автономного ESM Worker со статическими файлами |

Браузер отправляет запрос через HTTPS. Node проверяет сессию, передаёт идентификатор аккаунта Worker и добавляет операции резервирования. Worker проверяет формат запроса, выбирает локальный навык или провайдера и резервирует бюджет до каждого внешнего обращения. Для текста используются Gemini или OpenRouter, для изображений — Cloudflare, OpenAI или OpenRouter, для поиска — Tavily. Вход использует SMTP или Yandex Cloud Postbox. Ответ отображается в браузере. Асинхронные исследования сохраняют результат на сервере для получения после закрытия вкладки.

### Хранение

IndexedDB содержит проекты, диалоги и файлы, разделённые по аккаунту. SQLite в режиме WAL содержит профиль и анкету, сессии, бюджеты, рабочие снимки при включении синхронизации и явно опубликованные HTML-страницы. Приватная рабочая копия и публикации имеют отдельные маршруты и правила доступа. Секреты провайдеров хранятся в серверном окружении.

### Ограничения 0.1.0

Один активный процесс. Автодеплой перезапускает сервис с коротким перерывом. Локальная история зависит от браузера. Облачная синхронизация требует явного включения и ограничена 8 МБ. HTML-предпросмотр и публикации используют изоляцию браузера. Автономный Worker отдаёт интерфейс, а для авторизованного API используется серверная сессия VPS.
